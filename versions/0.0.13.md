# tach 0.0.13 (unreleased)

Bug-fix release on top of 0.0.12. x86 only.

## Fixed

- x86_64: boot page tables now identity-map 4 GiB (was 1 GiB). VMs with >1 GiB of RAM crashed with a page fault in `acpi_init` because the ACPI tables sit just below 4 GiB.
- x86_64: mapping a user page inside a split 2 MiB page lost the USER bit on the page-directory entry.
- Scheduler (SMP): `on_cpu` was cleared before `task_switch()` saved the old stack, so another CPU could resume a half-switched process. It is now released by the incoming context (`scheduler_finish_switch()`).
- SMP bring-up: PIT channel 2 delays are bounded by the TSC; if the PIT never reports terminal count (some hypervisors) delays degrade to short spins instead of hanging boot. `TACH_NOSMP` builds skip secondary CPUs. Each step now logs `smp: starting CPU n`.
- Kernel log timestamps use the real 100 Hz tick once the timer runs.
- Boot log no longer claims "no AHCI controller found": the AHCI/SATA driver is simply not implemented yet (VirtualBox defaults to SATA, so use an IDE controller there).
- `fat32.c` maybe-uninitialized warning.

## Removed

- Stale top-level `arch/` and `kernel/` (old boot code, unused) and the divergent copy `src/include/`.

## Not verified

- The VirtualBox hang is a hypothesis (SMP bring-up); it did not reproduce under QEMU. Try 1 CPU in the VM settings to confirm.
- The SMP scheduler race was intermittent (~1 in 10 boots); 12 consecutive `-smp 4` stress boots passed after the fix, which is not proof.
- i686 and ARM/RISC-V were built-checked only (i686 ISO could not be built here); only x86_64 was booted.
