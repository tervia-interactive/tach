## 1. What 0.0.11 is

tach is a free operating system written in C, designed around freedom, practicality, stability, universality and modularity (see the [README](../README.md) and [ROADMAP](../ROADMAP.md)).

Version 0.0.11 is an early development release. In practical terms:

- **On x86 (i686 and x86_64)** it is a working, bootable system: a kernel, a ring-3 userspace with `/sbin/init`, an interactive shell, 36 external tools, an in-memory `/tmp`, a `/proc` filesystem, and read/write FAT32 on ATA disks mounted at `/mnt`.
- **On every other architecture (arm32, aarch64, riscv32, riscv64)** only the **kernel** is present. There is no userspace, no shell and no tools. See [section 2](#2-architecture-support) and [section 15](#15-using-tach-on-other-architectures-fork-guide).

Main contents of this version:

| Area | In 0.0.11 |
|------|-----------|
| Kernel core | Ordered initcalls, panic with register dump, assertions, atomics, spinlocks, mutexes, rwlocks, refcounts, per-CPU data, timer wheel (100 Hz), supervisor watchdog |
| Memory | Bitmap physical allocator, refcounted frames, copy-on-write `fork`, per-process address spaces, kernel heap (`kmalloc` family), slab caches, W^X enforcement |
| Scheduling | Preemptive round-robin at 100 Hz, per-CPU run queues, SMP bring-up (x86 INIT/SIPI, ARM PSCI, RISC-V SBI HSM) |
| Processes | Static process table (32 processes), `fork`, `execve`, `waitpid`, signals, pipes, per-process cwd and fd table |
| Filesystems | VFS, USTAR initrd, tmpfs (`/tmp`), procfs (`/proc`), console devices (`/dev`), FAT32 read/write with long file names |
| Storage | Block layer with sector cache, MBR/GPT partitions, RAM disk, ATA PIO (LBA28/LBA48) |
| Input/output | VGA text console, 16550 UART serial, PS/2 keyboard |
| Userspace | crt0, small libc, `/sbin/init`, `/bin/sh`, 36 tools |

## 2. Architecture support

| Architecture | Kernel | Userspace (init, shell, tools) | Storage / FAT32 | Status in 0.0.11 |
|--------------|:------:|:------------------------------:|:---------------:|------------------|
| i686 | Yes | Yes (ring 3, `int 0x80`) | Yes (ATA PIO) | **Fully functional** |
| x86_64 | Yes | Yes (ring 3, `int 0x80`) | Yes (ATA PIO) | **Fully functional** |
| aarch64 | Yes | No | No | **Kernel only** |
| arm32 | Yes | No | No | **Kernel only** |
| riscv64 | Yes | No | No | **Kernel only** |
| riscv32 | Yes | No | No | **Kernel only** |

### What "kernel only" means

On aarch64, arm32, riscv32 and riscv64, 0.0.11 builds and contains the architecture-specific kernel pieces: boot code, exception/trap handling, MMU and page tables, interrupt controller (GIC / PLIC / ACLINT), timer-driven preemptive scheduling, and SMP bring-up. It is **not** an operating system on those architectures yet. Almost everything that makes a usable OS is missing:

- No EL0 / U-mode entry. `arch_user_supported()` returns `false` there, so ring-3 programs cannot run. The userspace build (`make userland`) is restricted to x86_64 and i686 and fails with an error for any other `ARCH`.
- No `/sbin/init`, no `/bin/sh`, none of the 36 tools in [section 8](#8-tool-reference-bin), no initrd payload.
- No block drivers: ATA PIO is x86-only (it uses x86 port I/O) and AHCI is an empty stub. No FAT32 automount.
- No input drivers beyond what the platform console provides (UART / SBI console).
- The x86 boot smoke test in CI does not exist for these targets; CI only checks that they build.

### If you want tach on a specific device (ARM, ARM64, RISC-V)

0.0.11 gives you a **kernel to build on**, not a finished system. To use it on a particular board or device you need to **fork the repository and build an OS on top of the kernel**: board bring-up, device drivers, a userspace entry path, a root filesystem and your own userland. [Section 15](#15-using-tach-on-other-architectures-fork-guide) lists what exists, what is missing and where to start. If you distribute a derivative, the attribution terms in [section 18](#18-license-and-attribution) apply.

## 3. Building

### 3.1 Prerequisites

Ubuntu / Debian (x86 targets and tests):

```bash
sudo apt-get install -y nasm xorriso grub-pc-bin grub-common mtools \
    qemu-system-x86 gcc gcc-multilib make
```

For the other architectures you need a cross toolchain:

| Target | Toolchain package (Debian/Ubuntu) | Prefix used by the build |
|--------|-----------------------------------|--------------------------|
| arm32 | `gcc-arm-linux-gnueabihf binutils-arm-linux-gnueabihf` | `arm-linux-gnueabihf-` |
| aarch64 | `gcc-aarch64-linux-gnu binutils-aarch64-linux-gnu` | `aarch64-linux-gnu-` |
| riscv32 / riscv64 | `gcc-riscv64-linux-gnu binutils-riscv64-linux-gnu` | `riscv64-linux-gnu-` |

Optional, for the FAT32 real-image test: `dosfstools`, `mtools`, `python3`.

### 3.2 Build commands

```bash
make                       # default architecture (x86_64)
make ARCH=i686
make ARCH=x86_64
make ARCH=arm32
make ARCH=aarch64
make ARCH=riscv32
make ARCH=riscv64
make all-archs             # see note below
make clean
make test                  # host tests (no QEMU needed)
make format
```

> `make all-archs` is mentioned in the README, but the 0.0.11 root `Makefile` does not define that target. Build each architecture with `make ARCH=<arch>`.

Userland and ISO:

```bash
make userland ARCH=x86_64          # crt0, libc, /sbin/init, /bin/sh, tools -> initrd.tar
make iso ARCH=x86_64               # builds userland automatically, then the GRUB ISO
make iso ARCH=x86_64 INITRD="$PWD/custom-initrd.tar"   # use your own USTAR initrd
```

`make userland` and `make iso` with the default payload only work for `x86_64` and `i686`.

### 3.3 Build outputs

| Output | Path |
|--------|------|
| Kernel image | `src/build/<arch>/tach.bin` |
| Bootable ISO (x86 only) | `src/build/<arch>/tach.iso` |
| Userland build | `src/build/<arch>/user/` |
| Initrd (USTAR tar) | `src/build/<arch>/user/initrd.tar` |
| Root filesystem staging | `src/build/<arch>/rootfs/` (`/sbin`, `/bin`) |
| Host test binaries | `src/build/host/` |

The ISO is built with `grub-mkrescue`. The generated `grub.cfg` has one entry, `tach`, with a 3-second timeout. x86_64 boots via **Multiboot 2** (`multiboot2` + `module2`), i686 via **Multiboot 1**. The initrd is attached as the first boot module.

### 3.4 Helper scripts

| Script | What it does |
|--------|--------------|
| `scripts/build.sh [arch]` | `make clean`, `make ARCH=<arch>`, and for x86 also `make iso` |
| `scripts/run-qemu.sh [arch]` | Runs the ISO (x86) or kernel binary (others) in QEMU |
| `scripts/format.sh` | Runs the code formatter |
| `scripts/run-tests.sh [arch]` | Builds with `TACH_TEST=1`. It only compiles; it does not run the tests (the script says so itself) |
| `scripts/fat32-realimg-test.sh` | Validates the FAT32 driver against images made with `mkfs.fat` + `mcopy` (run `make test` first) |

## 4. Running

### 4.1 x86 (the supported way)

```bash
# 64-bit
qemu-system-x86_64 -cdrom src/build/x86_64/tach.iso -boot d -m 256M -smp 2

# 32-bit
qemu-system-i386 -cdrom src/build/i686/tach.iso -boot d -m 256M -smp 2
```

Headless, with the serial console on your terminal (this is what the CI smoke test does):

```bash
qemu-system-x86_64 -cdrom src/build/x86_64/tach.iso \
    -display none -serial stdio -no-reboot -smp 2 -m 256M
```

Notes:

- **Boot the ISO, not `-kernel`, on x86_64.** QEMU's built-in multiboot loader only accepts 32-bit ELF. `scripts/run-qemu.sh` prefers the ISO when it exists.
- Output is mirrored to the VGA console and to COM1. Input works from the PS/2 keyboard and from the serial port.
- `-smp N` is supported. SMP and userspace boot are checked in CI with `-smp 2`.
- On VirtualBox, see [section 17](#17-troubleshooting) (multi-core hang with Hyper-V).

### 4.2 Attaching a disk (FAT32)

The ISO does not include a data disk. Attach one as a legacy IDE disk so the ATA PIO driver can see it:

```bash
# create a 64 MiB FAT32 image (host side)
dd if=/dev/zero of=disk.img bs=1M count=64
mkfs.fat -F 32 disk.img

qemu-system-x86_64 -cdrom src/build/x86_64/tach.iso -boot d -m 256M \
    -drive file=disk.img,format=raw,if=ide,index=0,media=disk
```

At boot, tach scans the block devices and mounts the **first one that holds a FAT32 volume** on `/mnt` (see [section 9.4](#94-fat32-and-mnt)). Details, limits and the `mount` / `umount` / `sync` tools are in [section 9](#9-filesystems-and-storage).

A disk image can also be passed as a **second Multiboot module**; it is exposed as the RAM disk `ram0`. The stock `make iso` only adds the initrd module, so this path is for custom boot setups and tests.

### 4.3 Other architectures (kernel only)

```bash
qemu-system-arm     -M virt -cpu cortex-a9  -kernel src/build/arm32/tach.bin   -nographic
qemu-system-aarch64 -M virt -cpu cortex-a57 -kernel src/build/aarch64/tach.bin -nographic
qemu-system-riscv32 -M virt                 -kernel src/build/riscv32/tach.bin -nographic
qemu-system-riscv64 -M virt                 -kernel src/build/riscv64/tach.bin -nographic
```

These start the kernel. There is no shell to interact with (see [section 2](#2-architecture-support)).

## 5. Boot sequence

On x86 the kernel prints its progress through `klog` to the VGA console and COM1. In order:

1. Early console, log subsystem, GDT/IDT/IRQ setup (x86 only).
2. Version banner: `version 0.0.11 starting (arch=...)`.
3. ACPI discovery, CPU topology.
4. Physical memory manager from the Multiboot memory map; virtual memory manager; kernel heap and slab caches.
5. Synchronization primitives, IPC control port.
6. Scheduler, per-CPU queues, timer, SMP bring-up, interrupts enabled. Logged as `scheduler: N CPU(s), per-CPU queues and preemption online`.
7. Syscall dispatch table.
8. PCI bus scan, legacy ISA DMA controller.
9. VFS; the Multiboot module 0 is imported as the USTAR **initrd**; tmpfs, devfs and procfs are initialized.
10. Block layer; Multiboot module 1 (if any) becomes `ram0`; ATA PIO probes `hda`..`hdd` and scans partitions; AHCI stub.
11. **FAT32 automount** on `/mnt`, or `no FAT32 volume found, /mnt not mounted`.
12. PS/2 keyboard, RTC, TTY and virtual terminal, watchdog.
13. `system initialized successfully`, then the userspace bootstrap:
    - if user mode is supported and `/sbin/init` exists in the initrd: `PID 1 executing /sbin/init in userspace`, then `tach init: PID 1 online`, then `tach userspace shell`;
    - otherwise an embedded in-kernel init and shell are started (see [section 6.1](#61-the-two-shells)).

If PID 1 ever exits, the kernel logs `userspace exited with status N` and halts the CPU.

## 6. Using the system

### 6.1 The two shells

tach has two shells. Which one you get depends on how it booted.

| | Userspace shell (`/bin/sh`) | Kernel shell (embedded) |
|---|---|---|
| When | Normal boot on x86 with the initrd | Fallback: no initrd, or an architecture without user mode |
| Runs in | Ring 3, started by `/sbin/init` | Kernel |
| Prompt | `tach:<cwd># ` | `tach (0.0.11)` banner, then its own prompt |
| Pipes `\|` (up to 4 stages) | Yes | No |
| `<` `>` `>>` redirection | Yes | Only `echo ... > file` / `>>` |
| `;` `&&` `\|\|` | No | Yes |
| `$?` expansion | No (use `status`) | Yes |
| Tab completion | No (Tab becomes a space) | Yes |
| Cursor editing | Backspace, Ctrl+U, Ctrl+W | Left/Right, Home/End, Delete, Ctrl+A/E/K/U/W/C/L |
| Extra builtins | `pid`, `kill` | `hostname`, `uptime`, `free`, `sleep`, `stat`, `mkdir`, `rmdir`, `mv` |

This document focuses on the userspace shell, because it is what a normal x86 boot gives you. Section 7.4 covers the kernel shell.

### 6.2 First steps

After boot you are at the prompt of the userspace shell:

```
tach init: PID 1 online
tach userspace shell
Type 'help' for commands.
tach:/# 
```

Try:

```
tach:/# help
tach:/# uname -a
tach:/# ls -l /
tach:/# cat /proc/meminfo
tach:/# ps
tach:/# echo hello > /tmp/hello.txt
tach:/# cat /tmp/hello.txt
tach:/# cat /proc/ps | grep init | wc -l
```

`init` supervises the shell: if you type `exit`, init prints `init: shell exited; restarting` and starts a new shell.

### 6.3 Typical tasks

**Look around**

```
ls                     # current directory
ls -l /bin             # mode and size
cd /proc && ls         # procfs files
pwd
```

**Work with files in RAM (`/tmp`)**

```
echo one > /tmp/a.txt
echo two >> /tmp/a.txt
cat /tmp/a.txt
cp /tmp/a.txt /tmp/b.txt
mv /tmp/b.txt /tmp/c.txt      # tmpfs cannot rename: mv copies, then removes
rm /tmp/a.txt /tmp/c.txt
```

**Process text**

```
seq 1 20 | sort -rn | head -n 5
cat /proc/syscalls | grep -i fork
find / -name '*.txt' | xargs cat
```

**Use a FAT32 disk** (see section 9.4)

```
ls /mnt
mkdir /mnt/docs
echo test > /mnt/docs/note.txt
sync
```

**Inspect the system**

```
ps                 # processes
free               # memory (from /proc/meminfo)
cat /proc/version
syscalls           # list of syscalls (see the note in section 11)
```

## 7. Shell reference

### 7.1 Command line syntax (userspace shell)

- **Words** are separated by spaces. A Tab typed at the prompt is turned into a space.
- **Quoting:** `'single'` and `"double"` quotes group words. A backslash escapes the next character. Quotes only work at the start of a word (a word that begins with a quote runs to the matching quote).
- **Redirection:** `cmd < file`, `cmd > file`, `cmd >> file`. The operators must be **separate words** (`cmd > file`, not `cmd >file`). They can appear anywhere in the command.
- **Pipelines:** `a | b | c`, **up to 4 stages**. The `|` must be a separate word. The exit status of a pipeline is the status of its last stage.
- **Limits:** a line holds at most 255 characters, a command at most 31 arguments, history keeps the last 8 distinct lines.
- **No** variables, globbing (`*` is passed literally; tools such as `find -name` do their own matching), `;`, `&&`, `||`, background jobs or command substitution.
- **Builtin vs external:** if the first word is a builtin, the builtin runs. Otherwise the shell runs `/bin/<word>` (or the path, if the word starts with `/`). To force the external version of a builtin that also exists in `/bin`, give the full path: `/bin/ls -a`. Inside a pipeline, builtins run in a child process, so builtins that change shell state (`cd`, `exit`) have no effect there.
- **Exit status:** `status` prints the status of the previous command. Unknown commands print `<cmd>: command not found or not executable` and return 127.

### 7.2 Line editing (userspace shell)

| Key | Action |
|-----|--------|
| Backspace (0x08 or 0x7F) | Erase the last character |
| Ctrl+U | Erase the whole line |
| Ctrl+W | Erase the last word |
| Up / Down | Navigate history (serial `ESC [ A/B` and PS/2 up/down both work) |
| Enter | Run the line |

There is no cursor movement inside the line.

### 7.3 Builtins (userspace shell)

| Command | Description |
|---------|-------------|
| `help` | Print the builtin list |
| `clear` | Clear the screen |
| `echo [args...]` | Print arguments separated by spaces. No `-n` in the builtin; `/bin/echo -n` has it |
| `uname [-a]` | `tach`; with `-a`, prints `tach 0.0.11 <arch> userspace` (from `/proc/uname`) |
| `ps` | Print `/proc/ps` |
| `id`, `whoami` | `uid=0(root) gid=0(root) pid=N`, and `root` |
| `pid` | Print this shell's PID |
| `pwd` | Print the working directory |
| `cd [path]` | Change directory (default `/`). Supports `.` and `..` and relative paths |
| `ls [-l] [path]` | List a directory (unsorted). `-l` shows mode and size. Directories get a trailing `/` |
| `cat <file>...` | Print files. With **no** operands it runs `/bin/cat`, so it reads stdin (works in pipes) |
| `history` | Show the last 8 commands |
| `kill [-sig] <pid>...` | Send a signal (default `SIGTERM`; `sig` is a number 1 to 31) |
| `touch <file>...` | Create empty files |
| `rm <file>...` | Remove files (no `-r`; use `/bin/rm -r` for directories) |
| `syscalls` | Print `/proc/syscalls` |
| `status` | Print the previous command's status |
| `true`, `false` | Return 0 / 1 |
| `exit [status]` | Leave the shell (init restarts it) |

> The built-in `help` text says `touch` and `rm` work "only under /tmp". That text is outdated: both use the normal VFS calls, so they act on any writable mount (for example `/mnt` once FAT32 is mounted). `rm` reports `file is in use` or `read-only file system` when the kernel returns those errors.

Directory and file management tools that are **not** builtins in this shell (`mkdir`, `rmdir`, `mv`, `cp`, `stat`, `find`, `mount`, ...) are the external programs in [section 8](#8-tool-reference-bin).

### 7.4 Kernel shell (fallback)

Used when the system boots without the initrd or on an architecture without user mode. Builtins:

`help clear echo uname hostname uptime free ps id whoami pwd cd ls cat stat mkdir rmdir rm touch mv sleep history status syscalls true false exit`

Differences from the userspace shell:

- Chain commands with `;`, `&&` and `||`. `$?` expands to the previous status (outside single quotes).
- `echo [-n] args [> file | >> file]` is the only redirection.
- `cd -` returns to the previous directory. Tab completes names.
- `mkdir`, `rmdir`, `rm`, `touch` and `mv` operate on writable mounts and take several paths (except `mv`, which takes exactly two). `mkdir`, `rmdir` and `mv` (rename) only succeed on FAT32 mounts; tmpfs does not support them.
- `sleep <seconds>`, `uptime` (`up H:MM:SS (N ticks)`), `free` (kB), `hostname`, `stat <path>`.
- Editing keys: Left/Right, Home/End, Delete, Backspace, Tab, Ctrl+A/E/K/U/W, Ctrl+C (cancel), Ctrl+L (clear), Up/Down (history, 8 entries).
- It can run ELF files from `/bin` (and absolute paths) like the userspace shell, if the initrd is present.

No pipes and no general redirection in the kernel shell.

## 8. Tool reference (`/bin`)

All tools are ring-3 ELF programs in the initrd. They share the small libc in `user/libc/` and are built from `user/bin/<name>.c`. Exit status follows the Unix convention (0 success, non-zero failure) unless noted. `-` as a file name means standard input in the tools that say so.

### 8.1 Text processing

| Tool | Usage | Notes |
|------|-------|-------|
| `head` | `head [-n N] [-c N] [file...]` | First N lines (default 10) or bytes |
| `tail` | `tail [-n N] [-c N] [file...]` | Last N lines (default 10) or bytes. Keeps only a fixed-size tail buffer, so very long input is truncated to the last part |
| `wc` | `wc [-lwcm] [file...]` | Lines, words, bytes |
| `nl` | `nl [-b a\|t] [file]` | Number lines; `-b a` all, `-b t` non-empty only |
| `rev` | `rev [file...]` | Reverse each line (bytes; lines over 1023 bytes are truncated) |
| `tac` | `tac [file...]` | Lines in reverse order |
| `sort` | `sort [-rnfu] [file...]` | Stable. `-r` reverse, `-n` numeric, `-f` ignore case, `-u` unique. Reads everything into the heap |
| `uniq` | `uniq [-cdui] [file]` | Collapse adjacent duplicates. `-c` count, `-d` only repeated, `-u` only unique, `-i` ignore case |
| `cut` | `cut -f LIST [-d DELIM] [-s] [file...]` or `cut -c LIST [file...]` | LIST like `1,3-5,7-`; positions start at 1 |
| `tr` | `tr [-d] [-s] SET1 [SET2]` | Ranges (`a-z`), escapes (`\n \t \\ \-`), classes `[:upper:] [:lower:] [:digit:] [:alpha:] [:alnum:] [:space:]`. `tr a-z A-Z`, `tr -d '\n'`, `tr -s ' '` |
| `hexdump` | `hexdump [-C] [-v] [-n BYTES] [-s SKIP] [file]` | Canonical hex+ASCII dump. Repeated lines collapse to `*` unless `-v` |
| `comm` | `comm [-1] [-2] [-3] file1 file2` | Compare two **sorted** files in three columns |
| `paste` | `paste [-d list] file...` | Join corresponding lines with TAB (or `-d` characters). Up to 8 files |
| `tee` | `tee [-a] [file...]` | Copy stdin to stdout and to files; `-a` appends |
| `seq` | `seq [-s sep] [first [step]] last` | Signed integers |
| `echo` | `echo [-n] [args...]` | External version, for `xargs` and pipelines |
| `cat` | `cat [-n] [file...]` | Concatenate files or stdin; `-n` numbers lines |

### 8.2 Searching

| Tool | Usage | Notes |
|------|-------|-------|
| `grep` | `grep [-ivcnlqFHh] [-e pattern] pattern [file...]` | Regex subset: `^ $ . * + ? [..] \c`. `-F` fixed string. `-i` ignore case, `-v` invert, `-c` count, `-n` line numbers, `-l` list files, `-q` quiet, `-H/-h` force/suppress file names. Exit 0 if something matched, 1 if not, 2 on error. Lines over 1023 bytes are truncated before matching |
| `find` | `find [path...] [-name GLOB] [-type f\|d] [-maxdepth N]` | `GLOB` supports `* ? [..]` |
| `cmp` | `cmp [-s] file1 file2` | Byte comparison. Exit 0 equal, 1 differ, 2 error. `-s` silent |

### 8.3 Files and directories

| Tool | Usage | Notes |
|------|-------|-------|
| `ls` | `ls [-l] [-a] [-1] [path...]` | **Sorted** listing. Hides names starting with `.` unless `-a`. The shell's builtin `ls` is unsorted and has only `-l`; run `/bin/ls` for this one |
| `stat` | `stat file...` | Type, size, mode, inode, links, uid, gid |
| `du` | `du [-s] [-b] [path...]` | Sum of file sizes (not blocks). Default KiB rounded up, one line per directory; `-s` total only; `-b` bytes |
| `cp` | `cp [-f] src dst` or `cp [-f] src... dir` | Regular files only. **`-r` is rejected** |
| `mv` | `mv src dst` or `mv src... dir` | Tries `rename()` first (atomic; works for directories on the same mount). If the mount cannot rename, it copies and then removes the source (regular files only; the source is removed only if the copy succeeded) |
| `rm` | `rm [-r] [-f] file...` | `-r` removes directories recursively, `-f` ignores missing files |
| `touch` | `touch file...` | Creates missing empty files. There is no timestamp syscall, so existing files are left untouched |
| `mkdir` | `mkdir dir...` | Mode 0755. **No `-p`** |
| `rmdir` | `rmdir dir...` | Empty directories only |
| `basename` | `basename path [suffix]` | |
| `dirname` | `dirname path` | |

### 8.4 System

| Tool | Usage | Notes |
|------|-------|-------|
| `free` | `free [-m]` | Physical memory from `/proc/meminfo`; `-m` in MiB |
| `mount` | `mount /dev/<disk> <dir> [fat32]` | Root only. Type defaults to `fat32` (`vfat` is accepted as an alias). With no arguments it prints a usage message; it cannot list mounts yet |
| `umount` | `umount <dir>` | Root only. Fails if `<dir>` is not a mount point or has open files |
| `sync` | `sync` | Flush cached sectors to disk |
| `xargs` | `xargs [-n N] [command [args...]]` | Reads words from stdin (quotes group words), appends them to `command` (default `echo`), in batches of N. The command is searched in `/bin` and **cannot be a shell builtin** |

### 8.5 Combining tools

```
cat /proc/ps | grep init | wc -l
find /tmp -type f | xargs rm
seq 1 100 | sort -rn | head -n 3
cut -d : -f 1 /tmp/data | sort | uniq -c
```

`find /tmp/x | xargs rm` works because `rm` exists in `/bin`; builtin-only commands would not.

## 9. Filesystems and storage

### 9.1 Layout

| Path | Type | Writable | Contents |
|------|------|:--------:|----------|
| `/` | VFS root | - | Virtual directory tree |
| `/bin`, `/sbin` | Initrd (USTAR) | No | The shell, `init` and the tools. Any other path inside the tar also appears as a directory |
| `/dev` | Console devices | - | `/dev/console`, `/dev/tty` (character devices). Disks are **not** listed here |
| `/proc` | procfs | No (read-only) | See 9.2 |
| `/tmp` | tmpfs (RAM) | Yes | See 9.3 |
| `/mnt` | FAT32 automount | Yes | First FAT32 volume found at boot, if any |

The VFS is path-based. Directories are real: `getdents` lists them and `stat`/`fstat` report type, mode and size in a fixed 32-byte structure. Each process has its own working directory (`chdir`, `getcwd`), inherited across `fork` and `execve`; relative paths, `.` and `..` are resolved by the kernel.

### 9.2 `/proc`

Text files generated on read. Each read at offset 0 builds a fresh snapshot (up to 2 KiB); later reads slice the same snapshot.

| File | Content |
|------|---------|
| `/proc/version` | `tach 0.0.11 <arch> (freestanding C kernel)` |
| `/proc/uname` | `tach 0.0.11 <arch> userspace` |
| `/proc/meminfo` | `MemTotal:` and `MemFree:` in kB |
| `/proc/self/status` | `Name`, `Pid`, `PPid`, `State`, `Uid`, `Gid` of the reading process |
| `/proc/ps` | Process table: PID, PPID, state, runtime ticks, name. `*` marks the current process |
| `/proc/syscalls` | Number and name of the listed syscalls |

Files opened for writing return an access error.

### 9.3 `/tmp` (tmpfs)

- Files live in kernel heap memory.
- **Up to 32 files**, names up to 48 characters, each up to **1 MiB**.
- Supports `open` with `O_CREAT`, `O_TRUNC`, `O_APPEND`, `unlink`, `lseek`.
- Reading the `/tmp` directory lists its files. It is **flat**: tmpfs has no `mkdir` and no `rename`, so there are no subdirectories, and `/bin/mv` inside `/tmp` falls back to copy + remove.
- A file that is unlinked while open is released only when the last descriptor is closed.
- Contents are lost on reboot.

### 9.4 FAT32 and `/mnt`

Driver features:

- FAT32 only (FAT12/FAT16 volumes are rejected). 512-byte logical sectors.
- **Read and write**: file read/write, truncate, create, delete, **rename**, `mkdir`, `rmdir`.
- **Long file names** (up to 255 UTF-8 bytes) and 8.3 names. Case-insensitive lookup for ASCII.
- FAT mirroring (all FAT copies are written when mirroring is on). FSInfo is kept in memory and written on `sync` / unmount.
- Files up to 4 GiB - 1 (FAT limit).
- Read-only devices are honored (`EROFS`).
- Cluster chains are loop-protected.

How a volume gets mounted:

1. **Automount at boot:** every block device (partitions and whole disks) is tried in order; the first FAT32 volume is mounted on `/mnt`. If there is none, the log says `no FAT32 volume found, /mnt not mounted`.
2. **Manually, as root:**

   ```
   mount /dev/hda1 /mnt fat32
   ls /mnt
   umount /mnt
   ```

   `<disk>` is a block device name such as `hda`, `hda1`, `ram0`, `ram0p1`. Block devices are found by name; they are not entries in `/dev`.

Always run `sync` (or `umount`) before powering off. Writes go through a write-back sector cache and are not on the disk until flushed. `umount` fails with a busy error if any file on that mount is open.

Known quirk: removing entries while listing a directory can make the listing skip the next entry (noted in the source of `rm`; `rm -r` is written to cope with it).

### 9.5 Block layer and drivers

| Item | Details |
|------|---------|
| Block layer | 512-byte sectors, write-back sector cache keyed by physical disk and LBA, so a partition and its whole disk always see the same data. Up to 32 devices |
| Partitions | MBR and GPT. Named by appending a number (`hda1`); disks ending in a digit use `p` (`ram0p1`) |
| ATA PIO | Legacy IDE channels at 0x1F0 and 0x170, master and slave, named `hda`..`hdd`. LBA28 and LBA48, polling, up to 128 sectors per command. **x86 only.** ATAPI and native-mode SATA devices are ignored |
| RAM disk | Second Multiboot module becomes `ram0` |
| AHCI | Not implemented in 0.0.11 (the driver is an empty stub; the boot log prints that no AHCI controller was found) |
| USB | Not implemented (planned) |

## 10. Processes, signals and memory

### 10.1 Processes

- Static process table, **32 processes** maximum, each with PID, PPID, state, credentials and runtime accounting.
- `fork` is copy-on-write: pages are shared read-only and separated on first write.
- `execve` loads **ELF32 / ELF64** executables (validated, `PT_LOAD` segments mapped). Tools are looked up in `/bin`.
- Every process runs as `uid 0 / gid 0` (root). There is no login and no permission enforcement beyond a few root-only syscalls (`mount`, `umount`).
- User stacks and heap grow on demand (user stack up to 8 MiB). An invalid user access becomes `SIGSEGV`.
- Scheduling is preemptive round-robin at 100 Hz, per CPU.
- A supervised-process watchdog can send `SIGKILL` for a missed deadline, with a bounded restart budget.

### 10.2 Signals

POSIX-style actions (`sigaction`), pending delivery and fatal defaults, plus `SIGCHLD`. `SIGKILL` and `SIGSTOP` cannot be caught.

| Number | Name | | Number | Name |
|:------:|------|-|:------:|------|
| 1 | SIGHUP | | 13 | SIGPIPE |
| 2 | SIGINT | | 14 | SIGALRM |
| 3 | SIGQUIT | | 15 | SIGTERM |
| 4 | SIGILL | | 17 | SIGCHLD |
| 5 | SIGTRAP | | 18 | SIGCONT |
| 6 | SIGABRT | | 19 | SIGSTOP |
| 7 | SIGBUS | | 20-29 | SIGTSTP, SIGTTIN, SIGTTOU, SIGURG, SIGXCPU, SIGXFSZ, SIGVTALRM, SIGPROF, SIGWINCH, SIGINFO |
| 8 | SIGFPE | | | |
| 9 | SIGKILL | | | |
| 10 | SIGUSR1 | | | |
| 11 | SIGSEGV | | | |
| 12 | SIGUSR2 | | | |

From the shell: `kill 12`, `kill -9 12`. The userspace libc header exposes the common subset (`SIGHUP`, `SIGINT`, `SIGQUIT`, `SIGKILL`, `SIGUSR1`, `SIGSEGV`, `SIGUSR2`, `SIGPIPE`, `SIGALRM`, `SIGTERM`, `SIGCHLD`, `SIGCONT`, `SIGSTOP`).

### 10.3 Pipes and descriptors

- `pipe`, `dup`, `dup2`; pipe ends are counted per descriptor, so EOF and `EPIPE` behave correctly across `fork` and process exit.
- Each process has its own descriptor table; standard streams are inherited from the console.

### 10.4 Memory

- Physical frame allocator (bitmap) populated from the Multiboot map; frames are reference counted.
- Per-process address spaces on x86, ARM, AArch64 and RISC-V page tables.
- Kernel heap (`kmalloc`, `kzalloc`, `krealloc`, `kfree`) with slab caches on top.
- **W^X** is enforced.
- User programs get `brk` and `mmap`/`munmap` (anonymous private mappings). `PROT_*` and `MAP_PRIVATE | MAP_ANONYMOUS` are the supported flags.
- The user program image is linked at `0x400000`; the kernel image must stay below that address (this is why kernel tables such as tmpfs and procfs are kept small).

## 11. System call interface

### 11.1 Calling convention (x86)

The userspace uses a software interrupt, `int 0x80`. Return values are in the first register; **negative values are `-errno`**.

| | Syscall number | Arguments (in order) | Return |
|---|:---:|---|---|
| x86_64 | `rax` | `rdi, rsi, rdx, r10, r8, r9` | `rax` |
| i686 | `eax` | `ebx, ecx, edx, esi, edi, ebp` | `eax` |

### 11.2 Syscall table

| Number | Name | Number | Name |
|:------:|------|:------:|------|
| 1 | `exit` | 36 | `sync` |
| 2 | `fork` | 37 | `kill` |
| 3 | `read` | 38 | `rename` |
| 4 | `write` | 39 | `mkdir` |
| 5 | `open` | 40 | `rmdir` |
| 6 | `close` | 41 | `dup` |
| 7 | `waitpid` | 42 | `pipe` |
| 10 | `unlink` | 63 | `dup2` |
| 11 | `execve` | 64 | `getppid` |
| 12 | `chdir` | 90 | `mmap` |
| 17 | `brk` | 91 | `munmap` |
| 19 | `lseek` | 106 | `stat` |
| 20 | `getpid` | 108 | `fstat` |
| 21 | `mount` | 141 | `getdents` |
| 22 | `umount` | 183 | `getcwd` |
| 24 | `getuid` | | |
| 27 | `sigaction` | | |

> **Quirk in 0.0.11:** `sync`, `rename`, `mkdir`, `rmdir`, `mount` and `umount` are registered and work, but they are missing from the name table, so the `syscalls` command and `/proc/syscalls` do not list them. `creat` (8), `link` (9), `time` (13), `mknod` (14), `chmod` (15), `lchown` (16), `setuid` (23) and `ptrace` (26) are defined in the header but not implemented (they return `ENOSYS`).

### 11.3 Structures and flags

```c
struct stat {          /* 32 bytes, identical on i686 and x86_64 */
    uint32_t st_ino, st_mode, st_nlink, st_uid, st_gid, st_reserved;
    uint64_t st_size;
};

struct dirent {
    uint32_t d_ino, d_off;
    uint16_t d_reclen;
    uint8_t  d_type;       /* DT_REG 1, DT_DIR 2, DT_LNK 3, DT_CHR 4, DT_BLK 5, DT_FIFO 6 */
    char     d_name[256];
};
```

Open flags: `O_RDONLY 0x0`, `O_WRONLY 0x1`, `O_RDWR 0x2`, `O_APPEND 0x8`, `O_CREAT 0x200`, `O_TRUNC 0x400`. Seek: `SEEK_SET 0`, `SEEK_CUR 1`, `SEEK_END 2`. Mode bits follow POSIX (`S_IFDIR 0040000`, `S_IFREG 0100000`, `S_IFCHR 0020000`, `S_IFIFO 0010000`).

User pointers passed to syscalls are validated; bad pointers return `EFAULT`.

## 12. Writing programs for tach

### 12.1 Add a tool

1. Create `user/bin/<name>.c`:

   ```c
   #include <tach.h>
   #include <tachc.h>

   int main(int argc, char** argv) {
       if (argc < 2) {
           eprintf("usage: hello name\n");
           return 2;
       }
       printf("hello, %s\n", argv[1]);
       return 0;
   }
   ```

2. Add `<name>` to the `BINS` list in `user/Makefile`.
3. `make iso ARCH=x86_64` (or `make userland ARCH=x86_64`). The program lands in `/bin/<name>`.

Programs are freestanding: no host libc. The initial user stack is a single page (it grows on demand, but the shell keeps its large buffers in `static` variables for that reason), so **avoid big local arrays**.

### 12.2 Available libraries

`user/include/tach.h` (syscall wrappers and basics) and `user/include/tachc.h` (extras):

- **Syscalls:** `read write open close unlink mkdir rmdir rename sync mount umount fork execve waitpid getpid getppid getuid pipe dup dup2 kill lseek stat fstat getdents chdir getcwd brk mmap munmap _exit`.
- **Memory and strings:** `malloc free calloc realloc` (brk-backed), `memcpy memmove memset memcmp memchr strlen strnlen strcmp strcpy strstr strrchr`, `strspn strcspn strpbrk strcasecmp strncasecmp strlcpy`, `path_basename`.
- **ctype:** `isdigit isalpha isalnum isspace isupper islower isprint isxdigit toupper tolower`.
- **Conversion:** `strtol strtoul abs`.
- **Formatted output:** `printf eprintf snprintf vsnprintf vdprintf write_all` (64-bit values supported without libgcc).
- **Utilities:** heapsort `qsort`, `getopt`, buffered line reader (`rb_init rb_getc rb_getline`), buffered writer (`wb_init wb_putc wb_write wb_flush`), regex matcher (`re_match`), `str_find`.

### 12.3 Custom initrd

The initrd is a USTAR tar that contains `sbin/` and `bin/`. To boot with your own:

```bash
make iso ARCH=x86_64 INITRD="$PWD/custom-initrd.tar"
```

If it contains `/sbin/init`, that program becomes PID 1.

## 13. Kernel overview

Source layout:

| Directory | Contents |
|-----------|----------|
| `src/kernel/` | Entry (`main.c`), log (`klog`), panic, timer wheel, watchdog, user-pointer validation, in-kernel tests (`ktest`) |
| `src/arch/<arch>/` | Boot code, GDT/IDT or exception vectors, paging/MMU, context switch, SMP, syscall entry, per-arch interrupt controller |
| `src/hal/` | Hardware abstraction layer: console, CPU, IRQ, time, SMP, I/O, memory map, user-mode hooks |
| `src/mm/` | PMM, VMM, kernel heap, slab, user memory, `mprotect` |
| `src/proc/` | Processes, scheduler, syscalls, signals, fd table, pipes, wait, ELF loader (static and dynamic scaffolding) |
| `src/fs/` | VFS, tmpfs, procfs, devfs, initrd (USTAR), FAT32 |
| `src/drivers/` | `block/` (blk, partitions, ramdisk, ATA PIO, AHCI stub), `char/` (UART 8250, PL011, SBI console, CMOS RTC), `input/` (PS/2), `video/` (VGA text) |
| `src/hw/` | PCI, DMA, ACPI, device tree (FDT) |
| `src/ipc/` | Message ports, semaphores, kqueue |
| `src/sync/` | Atomics, spinlocks, mutexes, rwlocks |
| `src/term/` | TTY line discipline, virtual terminal, kernel shell |
| `src/userland/` | Embedded fallback init and shell, userspace bootstrap |
| `src/boot/` | Multiboot 1/2, UEFI structures, SBI |
| `include/` | Public kernel headers |
| `user/` | crt0, libc, `init`, `sh`, tools |
| `link/` | Linker scripts, one per architecture |
| `tests/` | Host tests, in-kernel tests, userland tests |

Design rules (from the ROADMAP): the core stays small and must build and pass `make test` with every optional layer off; new code goes through the HAL and architecture-specific code lives only in `src/arch/<arch>`; a feature may be unavailable on an architecture but must degrade cleanly instead of breaking the build.

IPC primitives available to kernel code: message ports (XPC-style), counting semaphores (FIFO, blocking through the scheduler) and kqueue notifications.

## 15. Using tach on other architectures (fork guide)

This section is for people who want tach on aarch64, arm32, riscv32 or riscv64 hardware (or on any device that is not a PC).

### 15.1 What you get from 0.0.11

| Present in the kernel for these architectures | Where |
|-----------------------------------------------|-------|
| Boot entry, linker script | `src/arch/<arch>/boot.S`, `link/<arch>.ld` |
| Exceptions / traps | `src/arch/<arch>/exceptions.S` or `traps.S`, `exception_handler.c` or `trap_handler.c` |
| MMU and per-process page tables | `src/arch/<arch>/mmu.c` |
| Interrupt controller | GIC (arm32, aarch64), PLIC and ACLINT (riscv) |
| Context switch, timer-driven preemptive scheduling, SMP start | `context.S`, `smp.c` (ARM PSCI `CPU_ON`, RISC-V SBI HSM) |
| Division helpers for targets without hardware divide in libgcc | `aeabi.c` (arm32), `divdi3.c` (riscv32) |
| Console | PL011 UART, SBI console |
| Device tree parsing | `src/hw/fdt.c` |
| Architecture-independent kernel | All of `src/mm`, `src/proc`, `src/fs`, `src/ipc`, `src/sync`, `src/term` |

### 15.2 What is missing

To turn the kernel into an OS on these targets, you have to provide:

1. **User mode entry.** Implement `arch_user_supported()` returning `true`, `arch_user_init`, `arch_set_kernel_stack` and `arch_enter_user`, plus the syscall trap path (`svc` on ARM, `ecall` on RISC-V) mapped onto `syscall_dispatch`. The x86 versions in `src/arch/x86_64` and `src/arch/i686` (`user.c`, `user_entry.S`, `syscall_entry.c`) are the model.
2. **Userland build.** `user/Makefile` stops with an error for any architecture other than x86_64 and i686. Add compiler flags, a `crt/<arch>.S`, and the linker emulation for your target. The sources in `user/` are plain C.
3. **A root filesystem.** The initrd loader works from a Multiboot module on x86. Other boot paths (device tree `/chosen` initrd, firmware-loaded image) need glue code.
4. **Storage drivers** for your hardware (SD/MMC, virtio-blk, NVMe, eMMC...). Register them through `blk_*` in `src/drivers/block/blk.h`; FAT32 and partition parsing then work unchanged.
5. **Input and display** drivers for your device, plus a console that suits the board.
6. **Board support:** device-tree driven discovery of peripherals, clocks, pin setup.
7. **Validation:** the CI boot smoke test only exists for x86; write your own for your target.

### 15.3 How to start

1. Fork `tervia-interactive/tach` and read `ROADMAP.md` (the milestone "Finish userspace isolation on arm32, aarch64, riscv32, riscv64" is exactly this work).
2. Get the kernel to boot on your board or in QEMU `virt` (`make ARCH=<arch>`, commands in [section 4.3](#43-other-architectures-kernel-only)).
3. Add the user-mode transition and syscall entry (item 1 above), then build the userland for the architecture (item 2).
4. Bring up a root filesystem and the drivers your device needs.
5. Keep architecture-specific code inside `src/arch/<arch>` and go through the HAL so the other targets keep building.

### 15.4 Attribution

A derivative OS must carry the attribution in `NOTICE` (see [section 18](#18-license-and-attribution)).

## 16. Known limitations

General:

- Early-stage software. Many components are stubs; expect bugs and missing features.
- Single user (root), no login, no permission checks on files.
- No networking, no USB, no graphics beyond VGA text mode, no sound.
- No `/dev` entries for disks; no mount table listing (`mount` without arguments cannot show mounts).
- `touch` does not set timestamps; `mkdir` has no `-p`; `cp` has no `-r`.
- Process table limited to 32 processes; `/tmp` limited to 32 files of 1 MiB.
- `sort`, `tac` and similar tools load their input into memory; `tail` keeps only a bounded tail.
- Shell: no variables, globbing, job control or `;` `&&` `||` in the userspace shell; no cursor movement inside the line; pipelines up to 4 stages; redirection operators must be separate words.
- Outdated text: the userspace shell's `help` still says `touch` and `rm` work only under `/tmp`; the `syscalls` list omits six implemented syscalls; the README mentions `make all-archs`, which does not exist.
- FAT32: 512-byte sectors only; no FAT12/FAT16; `.` and `..` entries are not listed.
- x86 only: ATA PIO is polling-based (slow); AHCI/SATA native mode is not supported.
- Non-x86 architectures: kernel only (section 2).
- Releases built by CI attach x86 and ARM artifacts only; the `riscv32`/`riscv64` kernels are built but not attached by the release job.

## 17. Troubleshooting

| Symptom | Cause and fix |
|---------|---------------|
| In **VirtualBox** the boot hangs when the VM has more than 1 CPU | Windows **Hyper-V** is active, so VirtualBox runs on the Hyper-V (NEM) backend. Disable Hyper-V / the Windows hypervisor platform, or run the VM with 1 CPU. QEMU is not affected |
| `qemu-system-x86_64 -kernel ...` fails or prints a multiboot error | QEMU's loader only takes 32-bit ELF. Boot `tach.iso` instead |
| `ERROR: grub-mkrescue not found` / `xorriso not found` | `sudo apt install grub-pc-bin grub-common xorriso mtools` |
| `Userspace isolation is currently supported only on x86_64 and i686` | You ran `make userland`/`make iso` for another architecture. Section 2 and 15 |
| `no FAT32 volume found, /mnt not mounted` | No FAT32 disk was attached as IDE. Use `-drive ...,if=ide`, format with `mkfs.fat -F 32`, or mount manually (section 9.4). FAT12/FAT16 and SATA/AHCI-only disks are not supported |
| `mount: cannot mount ... (root only; needs a FAT32 volume)` | Wrong device name, not a FAT32 volume, or not root. Block devices are `hda`, `hda1`, `ram0`... |
| `umount: ... failed (not a mount point, busy or not root)` | A file or directory on it is open, or your cwd is inside it. `cd /` first |
| Files on `/mnt` missing after reboot | Run `sync` or `umount` before powering off; writes are cached |
| Writing to `/tmp` fails | 32 files or 1 MiB per file reached (section 9.3) |
| `command not found or not executable` | Not a builtin and not in `/bin`. Check `ls /bin`. Note that `xargs` cannot run shell builtins |
| `cat` seems to hang | `cat` with no file argument reads standard input and waits. The shell does not interpret Ctrl+D as end of input, so give it a file or use it in a pipe |
